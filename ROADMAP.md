# 🗺️ Roadmap та план розвитку Plantshelf

Цей документ фіксує поточний стан проекту, заплановані покращення та ідеї для майбутніх релізів.

## ✅ Поточний статус (v1.0.1)
- Повна реалізація базового функціоналу: полиці, енциклопедія, AI-додавання через Gemini.
- Інтеграція з системним календарем та експорт у `.ics`.
- Режим карантину з журналом лікування.
- Апаратний люксметр.
- In-App Updater через GitHub Releases.
- Повна сумісність з бекапами Brunq.

  - Відсутності інтернету (fallback на офлайн-енциклопедію).
- [x] Логування помилок у локальний файл (без телеметрії) для діагностики.

## 🚀 Реліз v1.0.2 (Готово до випуску)

### 1. Розширення історії догляду
- [x] **Swipe-to-Dismiss** для видалення записів з історії (поливу, добрив) через `ItemTouchHelper`.
- [x] **Undo-Snackbar** (3-5 секунд) для скасування випадкового видалення.

### 2. Розумне підживлення
- [x] Додати поля `recommendedFertilizers`, `fertilizeIntervalSummerDays`, `fertilizeIntervalWinterDays` у сутність `Plant`.
- [x] Оновити Gemini Prompt для автоматичного заповнення цих полів.
- [x] Нова секція "🧪 Підживлення" у `PlantDetailActivity`.

### 3. Масова синхронізація з календарем
- [x] Кнопка "Синхронізувати весь графік" у календарі та головному меню.
- [x] Використання `ContentProviderOperation.applyBatch()` для швидкої пакетної вставки подій.
- [x] Фонове виконання через `ExecutorService` з `ProgressBar` для UX.

### 4. Автоматичне очищення календаря
- [x] Зберігати `calendarEventId` у локальній БД при створенні події.
- [x] При видаленні рослини автоматично видаляти пов'язані події з `CalendarContract.Events`.
- [x] Fallback-механізм: пошук подій за унікальним `DESCRIPTION` (формат `Plantshelf_ID:123`).

### 5. Архітектурне покращення
- [x] Створити синглтон `CalendarSyncManager` для інкапсуляції всієї логіки роботи з `ContentResolver`.

### 6. Сповіщення та нагадування (Push Notifications)
- [x] Системний запит дозволу на сповіщення `POST_NOTIFICATIONS` на Android 13+.
- [x] Діалог налаштування нагадувань з вибором часу перевірки (TimePickerDialog) та тестовою відправкою.
- [x] Фоновий планувальник `NotificationScheduler` через `WorkManager` з урахуванням обраного користувачем часу.
